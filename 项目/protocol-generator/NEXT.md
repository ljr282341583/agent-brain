## 已知坑

- **导出文件名统一走 `buildExportFileName()`**:新增导出入口或调整命名规则时只改该函数;直接拼 `${...}.docx` 会绕过统一规则(2026-10-23 教训)。
- **文件名第三段口径分模块**:协议书/全套卷宗 = 纠纷类型,个人卷宗 = `个人卷宗`,调解记录表 = `调解记录表`,治安 = 「治安调解申请书 / 治安纠纷」;别"顺手统一"成纠纷类型(用户实测已纠正过一次)。
- **文书当事人串必须走共用函数**:`getPartyGroupsText()`(纯文本)/`getPartyGroupsUnderlinedHtml()`(下划线 HTML)/`getApplicantParties()`/`getRespondentParties()`。直接写 `state.parties.map(...).join('与')`(会把第三方串进来)或 `find(p => p.type==='applicant') || parties[0]`(只取第一人)就是 2026-10-03 修掉的"多当事人只填前两人"事故的根因。
- **治安 docx 不要用 `exact + nth:0` 填表格**:那是"全局第一个匹配",两人取值相同(如都是"男"、户籍地址相同)会写串;表格取值一律用 `setDocxRowCellText()` 按单元格填。
- **`replaceDocxTexts` 支持 `\n → <w:br/>`**(2026-10-03 新增):治安协议书多人分组换行依赖它;改写这段时别把 `\n` 拆行逻辑删掉。
- **测试脚本在 git 仓库外**:工作区根的散件(各版本 HTML 副本、`_test_*.js`、`_测试解包\` 等)不受 git 保护,换机器/清工作区会丢。
- **测试桩必须复刻真实语义**:优先从 HTML 提取真实函数注入,不要手写桩;v5.10 的 docx 类改动靠"Node + 真实模板 + 真实 zip + 解包校验"验证,样例见 `_test_v510_parties.js` 与 `_test_v5101_filename.js`。
- **版本号混乱(仍未整理)**:方案二文件名叫 v6.0、内容实为 V6.3(与 `历史版本\V6.3授权码版\` 哈希一致);判断功能一律以 README 更新日志为准。(README「版本演进」表已按「方案一升序 + 方案二 V6.x 单列表尾」修正;v5.3 仍无对应行。)
- **老内核兼容是雷区**:Chromium 80~102 不支持 `deflate-raw`,docx 导出必须走 `dsh-compat` 块的 puff 兜底;删掉兜底或只在新内核测过就发布,v5.5.1 修过一次这种事故。
