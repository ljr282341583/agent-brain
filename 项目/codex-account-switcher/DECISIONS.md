# DECISIONS — codex-account-switcher

> 只记录已拍板的方案 / 技术决策，只追加不删改（被后条取代时在旧条目末尾追加 ⚠️ 取代标注，属追加非改写）；"讨论中 / 待确认"的内容只进 JOURNAL，不进本文件。

## 2026-10-21 图标 v2：渐变底 + 白色「⇄」，按尺寸单独渲染

- **决定**：图标改为「圆角方块 + 蓝 `#2563EB` → 天蓝 `#0EA5E9` → 绿 `#059669` 对角渐变 + 白色双向箭头 ⇄」；16/24/32/48/64/128/256 共 7 个尺寸**各自按 4 倍超采样渲染**，≤32px 自动加大箭头笔画；用 Pillow 的 `append_images` 把各尺寸原图直接写进 ICO，而不是让 Pillow 从 256 大图缩。
- **理由**：v1（深蓝底 + 细蓝绿双弧 + `>_`）在深色桌面上几乎糊成一整块黑，16px 完全不可辨，用户反馈"桌面图标看着像空白 / 不好看"。v2 提高了白箭头对比度、小尺寸可辨认，并保留蓝绿配色与程序的 ACCENT/OK 一致。
- **否决**：只调 v1 的配色；只画一张 256 交给 Pillow 统一缩（小尺寸会糊）。

## 2026-10-21 桌面快捷方式图标直接取 exe 内嵌资源

- **决定**：`.lnk` 的 `IconLocation` 写 `<exe 完整路径>,0`，不再指向项目里的 `icon.ico`；重建快捷方式后再跑 `ie4uinit.exe -show` + 广播 `SHChangeNotify(SHCNE_ASSOCCHANGED)` 刷新图标缓存。
- **理由**：指向外部 ico 时，ico 换版 / 移动 / 图标缓存过期都可能让桌面图标变空白（本次用户遇到的就是"桌面上空白"）；exe 内嵌图标随程序走，最稳。
- **否决**：保留指向 `icon.ico`；靠"让用户重启资源管理器"当唯一修法。

## 2026-10-21 dev-shot2.ps1 结束进程改用 `taskkill /T`

- **决定**：截图脚本收尾从 `Stop-Process -Id $proc.Id -Force` 改为 `taskkill.exe /PID $proc.Id /T /F`。
- **理由**：PyInstaller onefile 的父进程只是引导器，真正窗口在子进程里；只杀父进程会留下隐形子进程——本次就残留了两个实例，并锁住 `portable\Codex账号切换器.exe`，导致打包最后一步 `Copy-Item` 失败。修复后截图零残留。
- **否决**：给每个子进程再单独 `Stop-Process`（拿不全、易漏）。

## 2026-10-21 「保存失败 WinError 5」先证权限面再改代码，不轻易加容错分支

- **决定**：遇到 `.codex\accounts` 创建被拒（WinError 5）时，先做**最小权限复现**（提权 shell / 经 explorer 启动的普通 python / 同款 PyInstaller 冻结 exe 三种上下文）确认是否真无写权限；证明是瞬时被挡后，**人工建档兜底**（直接创建 `accounts` 并替用户存下第一份快照），暂不改代码。只有再次复现才加"重试 + 存储位置回退"。
- **理由**：三种上下文实测都能创建并写入，说明不是代码 bug；`.codex` 上存在 46 条孤儿 SID 的 DENY ACE 与 `CodexSandboxUsers(RX)`、且 `codex-windows-sandbox-service` 常驻，最可能是 Codex 沙箱在保护该目录时临时挡了一下。盲目加"改存到别处"会掩盖真权限问题、还偏离"快照和凭据放一起"的设计。
- **否决**：直接把快照目录改到 `%LOCALAPPDATA%` 或 exe 同级（会让"存档"和"被切换的文件"分居两地，且没解决切换时写 `.codex` 的同一权限面）；把 WinError 5 静默忽略。
