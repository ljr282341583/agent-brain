| 执行位置 | 写工作区外（%TEMP% / %LOCALAPPDATA%） |
| --- | --- |
| `<仓库>\app\runtime\node.exe` | **全部 EPERM** |
| `<仓库>\.probe-tmp\node.exe`（工作区内新目录） | **全部 EPERM** |
| `%TEMP%\node-copy-probe.exe` | 全部 OK |
| `G:\ai\probe-node\node.exe` | 全部 OK |
| `C:\Program Files\nodejs\node.exe` | 全部 OK |

→ **可观测规则：进程镜像位于会话工作区内的进程，写工作区外一律 EPERM；同一二进制放到工作区外即不受限。**
（"沙箱按镜像路径判定"是对机制的推断；上表是实测。）

- **连带解释**：`afterPack.js` 的 `resolveNpmRunner`（L85-96）**优先用仓库内的侧车
  `app\runtime\node.exe`**，因此**从 agent 会话内跑 `npm run build` / `build:dir` 必挂在这一步**；
  这也正是上一轮笔记里 `npm run build:dir` 冒烟 [3]/[4] 报红（[3] `EPERM: mkdtemp`）的**同一根因**
