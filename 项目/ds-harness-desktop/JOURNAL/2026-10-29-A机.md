## 本次做了什么

- **引擎升级故障定位**：dsh 从 0.2.0-rc.2 升到 0.2.1-rc.4 后应用起不来。根因不是引擎、也不是壳：
  profile 里两个**本地自研插件**（`dsh-orb`、`dsh-project-ledger`）把 `@deepseek-ai/dsh-tools`
  写进了 `dependencies` 且钉死 `0.2.0-rc.2` → 旧 `dsh-tools` 被拖进 profile → `tools` 行被判
  不兼容并被禁用 → 依赖 `tools` 的十几个插件全部 pending（`agent-loop`、`tool-working-directory`、
  `spill-policy`、`mcp-resources`、`tool-agent-team`、`dsh-project-ledger` …）→ `startup failed`。
  用户手动修复：插件改 `peerDependencies: ">=0.2.0-rc.2 <0.3.0"` + 重装依赖 + 手动激活。
- **项目定位拍板**（见 DECISIONS）：继续用自己的桌面端；理由是**手机访问是刚需**——官方桌面端把引擎
  钉死 `--host 127.0.0.1 --port 0`（`apps/desktop-host/src/index.ts`），手机根本连不进，且强制更新、
  不能锁引擎版本；官方 Web 端虽可 `--host <尾巴网IP>` 但那是"另开一个实例"，不是遥控电脑上同一个。
- **壳补齐三条能力**（已实现并体检通过）：
  1. **升级前 profile 预检**：`updater.precheckProfile()` 用候选版本对**真实 profile** 跑
     `dsh --profile web --dump-config`，命中 `disabling profile plugin row` / `startup failed` 等
     即丢弃并保持原版本，不激活（`updateToLatest` 新增 `profile-precheck` 阶段）。
  2. **一键「回到上一个版本」**：`updater.rollbackToPrevious()` + 托盘菜单项 + 错误页按钮
     （错误页现在三按钮：重启服务 / 回到 vX / 打开 profile 目录）。
  3. **`npm run verify:profile`**：拿当前生效的 dsh 对真实 profile 做预检，退出码 0/1/2，
     补上 `verify:smoke`（干净 DSH_HOME、不带第三方插件）永远抓不到的盲区。
  4. 附带：单实例锁拿不到时**弹窗说明**（以前静默退出＝"双击没反应"）。
- **产物目录改名**：`产出\` → `dist\`（`electron-builder.yml` + `smoke.test.js` + `build-smoketest.js`
  + 6 份当前文档同步；历史目录整体改名为 `历史产物\` 并加进 `.gitignore`）。
- **"工作区里的 exe 双击没反应"根因定位**（耗时最久，见 DECISIONS 第 5 条）：
  会话工作区根目录带 **Low integrity（低完整性）标签**，agent 会话内构建的产物全部继承该标签 →
