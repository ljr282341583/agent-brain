## 关键结论 / 决策摘要

- **降级判据必须窄**：只有「从未成功加载过 UI + 仍在启动阶段（60 秒内，或 token 等待未结束）」才算启动失败；
  运行中途崩溃改为**同一版本**限次退避重启（3 次 / 30 分钟滑动窗口；跑满 10 分钟且起过 UI 则清空预算）。
- **回退前先问「回退有用吗」**：新增 `updater.checkProfileBundles`，判据与上游 `dsh-app-boot` 的
  `packageDirFromAnchor` **完全一致**（`createRequire(anchor).resolve.paths()` 父目录链 + 必须存在
  `package.json`）。依据：本机 profile 11 个 bundle 中有 **2 个**只在 dsh ≥ 0.1.7 存在，内置 0.1.5-rc.1
  永远解析不了 → 「回退到内置版本」在这台机器上不是保底，而是永久锁死。
- **上游行为差异（纠正报告第 8 节建议 1）**：0.1.7-rc.2 遇到解析不了的 bundle **只跳过并告警**
  （`dsh: skipping profile bundle …`），0.1.5-rc.1 才是 throw / 整个 boot 失败 → 该建议上游在新版已实现；
  也说明「内置版保底」在 profile 含新版本专属 bundle 时天然不成立。
- **兜底自愈**：真回退后若内置版也起不来，自动把 `state.json` 恢复回被停用的覆盖版本（只一次），
  绝不停在注定起不来的版本上。
- 详细决策见 `DECISIONS.md` 同日三条（含被推翻的口径）。
