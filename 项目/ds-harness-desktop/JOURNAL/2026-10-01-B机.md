## 本次做了什么

- **故障**：用户报「command code 插件失效」（设置页整页消失）。根因不是插件坏，是
  **运行时被换**——`%APPDATA%\ds-harness-desktop\dsh-update\versions\0.2.0-rc.2\install.json`
  记 `installedAt 2026-10-01T01:15:53Z`，DSH 自动升到 **0.2.0-rc.2**。
- **报错原文**（`dsh-child.log`）：`dsh: skipping profile bundle "@mars-sea/dsh-commandcode-provider":
  Error: Plugin …@0.11.11 is incompatible with dsh 0.2.0-rc.2: peerDependencies {…}`。
  0.1.x 的 `@deepseek-ai/*` peer 全不匹配 → profile 启动按 peer 门禁**整包跳过**；
  同一天 `dshmarket@1.58.0` 也被跳过（用户知情后拍板两个一起修）。
- **判定手法（不启动服务）**：`dsh --profile web --dump-config | Select-String 'skipping|incompatible'`
  —— 有 `skipping profile bundle` 行即被跳过；无该行且组合树里能看到插件行 = 已装载。
- **先救急后正解**：先 `dsh plugin allow-version "@mars-sea/dsh-commandcode-provider@0.11.11"
  --dsh-version 0.2.0-rc.2 --accept-risk --profile web` 让旧版可起；随即升级为正解——
  provider **0.11.11 → 0.12.2**（`engines.dsh` 恰为 `0.2.0-rc.2`，2026-10-01 当天发布）、
  `dshmarket` **1.58.0 → 1.66.7**（peer 已含 `^0.2.0-rc.1`，门禁放行）。命令：
  `dsh plugin --profile web add <pkg>@<version>`。
- **顺带挖出第二个坑（用户此前已中招一周）**：0.1.7 起 DSH **移除了 `settings.yaml`**，
  启动时 `SettingsForms.importLegacyDocument()` 把它改名为 `settings.yaml.imported` 再把各分节
  逐个写进 `profiles\web\cordis.patch.yml`。**09-24 19:42 那次迁移时插件还没装**

  `cordis.patch.yml` 末尾；改前备份 `cordis.patch.yml.bak-ccfix-20261001`。
