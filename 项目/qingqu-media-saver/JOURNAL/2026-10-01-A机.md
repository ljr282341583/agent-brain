### 2. 用户报「一条抖音链接存下来是 2 秒的广告」

- 用**真实页面 + App 源码原样注入的 TAP_JS/EARLY_JS** 复现（新探针 `webview-cdp-probe23.mjs`，对应 CDP 的 new-document 注入）：App 在 **+2411ms** 就回传了 `id 正确`但视频是 **`uuu_265.mp4`** 的结果 → Java 侧身份校验放行 → 定案；而主播放器的干净 `<source>` 要到 **+2582ms** 才挂载，**晚 171ms**。
- 那段 `uuu_265.mp4` 是**抖音 PC 网页页头的吉祥物加载片**（白兔抱红包，2.6s / 1080x1920 / HEVC，挂在静态资源 CDN `douyinstatic.com`）。抽帧看过，就是用户说的"两秒广告"。
- **A/B 对照更糟**：换一条用户以为"可用"的链接，同样中招 → 不是偶发，是**竞态**。
- **根因**：`TAP_JS` 的 `takePlay()` 语义是「页面上第一条非空视频即可」，没有任何"这是不是作品本体"的判据；而 `meta.aweme_id` 来自页面标题（正确），所以 Java 侧的 id 校验**防得住"别人的作品"，防不住"页面自己的片子"**。

### 3. 用户报「动图只显示第一张 / 下载第一张」

### 4. 用户报「抖音视频下载带水印」

- **逐个地址下载 + 抽帧肉眼核验**：

  | 地址 | 实测 | 水印 |
  | --- | --- | --- |
  | 接口 `play_addr`（App 实际选的） | 1080x1920 / 43.77s | 干净 |
  | DOM `*.douyinvod.com` ×2 | 576x1024 | 干净 |
  | DOM `/aweme/v1/play/?biz_sign=` | 576x1024 | 干净 |
  | 移动页回落 `/aweme/v1/playwm/` | 720x1280 / **46.751950s** | **水印** |

- 水印地址 **+1640ms 就到**，比桌面路径还快。`probe25` 进一步确认：移动页 `_ROUTER_DATA` 的作品节点**只有 `play_addr` 这一个地址**（无 `bit_rate`、无 h264、无 download 变体）→ **回落路径物理上拿不到干净直链**。
- 真机反馈（结果页提示「当前仅取到平台带标识的公开版本」）**坐实了走的是移动页回落**。排除了三个设备差异假设：桌面 UA + 触摸仿真（抖音发触摸屏）、禁止自动播放（模拟 WebView 默认）、移动 UA，**三种情况下桌面路径都仍拿到干净 douyinvod**。
- v2.3.5 的「文档开始前注入」没解决 → v2.3.6 改为**把回落的水印端点改写成无水印直链**。

### 5. ⚠️ 我自己犯的错（本次最大教训）

v2.3.6 里我加了个探测校验 `urlServesMedia()`：用 `Range: bytes=0-1` 探，再要求 `Content-Length > 1000` 才通过。**但跟随 302 后返回的是 206，而 206 的 `Content-Length` 只是片段长度（实测 2 字节）** → 判定永远 false → **「换干净地址」被静默跳过**，用户装了 v2.3.6 说"还是一样的问题"。

真实响应头（实测）：
```
206 Partial Content / Content-Type: video/mp4 / Content-Length: 2 / Content-Range: bytes 0-1/4103700
```

v2.3.7 改为优先读 `Content-Range` 的总长度（4103700 > 1000 → 通过），206 一律放行，`text/html` 拒绝；并把判定逻辑**先用真实响应头离线复算通过再打包**。
