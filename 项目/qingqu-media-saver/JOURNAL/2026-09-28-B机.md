### 1. 定位根因（可复现，不是 2.2 的代码 bug）

- 用 `data\qingqu.db` 里的**真实链接**（抖音 video / note / slides 各一类）复现，拿到确切报错体：
  `403 Blocked by ArgusSecurityPlugin Uifid Not Found`（46 字节）。
- 穷举排除：4 种 UA × 4 种 Referer/cookie 组合（16 次全 403）、iesdouyin 域名下的同接口、补全套 web 参数、桌面首页自举 cookie（只下发 `__ac_nonce`）、手工伪造 `UIFID`、老 `iteminfo` 接口（200 但 0 字节）、`iesdouyin/share/*` 分享页（降级为 **2492 字节 WAF 挑战页**）、`/video/{id}` 打开图文作品、爬虫 UA 的 SEO ld+json（只有标题/封面）。
- 结论：详情接口现在挂在字节 **Argus 安全网关**后，要求真实浏览器环境生成的 `UIFID`。
- 对照：**小红书链路完全正常**（图集 7 图 7 实况、视频 masterUrl 720x1280），本次只有抖音受影响。

### 3. 三轮实现与两次真机失败（关键过程）

- **v2.3**：新增隐藏 WebView 取数器，桌面 UA 优先；`parseDouyin` 改「接口先试 → 403 回落 WebView」；slides 短链改指；webp 扩展名修正。**真机失败**。
- **v2.3.1**：怀疑 1×1 视口不触发播放器懒加载 → 改全屏透明遮罩；补 `EARLY_JS` 在页面脚本前装钩子；去掉 UA 里的 `; wv`；失败信息带上真实页面状态。**真机仍失败**（报 `网页取数抖音页面未返回作品数据`）。
- **v2.3.2（用户确认可用）**：用 CDP 抓桌面页全部网络请求，查到**详情接口其实成功返回了**（`status_code=0`、76,355 字节，`aweme_detail.video.play_addr` 是 `v26-web.douyinvod.com` **干净直链**）。数据一直在页面里 —— 问题是我的钩子挂错了事件：**抖音用 axios，axios 靠 `onreadystatechange` + `responseText` 读响应，而我原来只监听了 `'load'` 事件，永远抓不到**。改为覆盖 `XMLHttpRequest.prototype.responseText` 访问器（EARLY_JS 与 TAP_JS 双层），成功。

### 4. 验证方式也改了（教训）

v2.3/v2.3.1 之所以「验过却还是坏的」，根子在我**手写理想的 DOM 数据**喂给验证器，只证明了逻辑自洽。v2.3.2 改为：①把详情接口的**真实响应从浏览器抓下来存成 payload**；②验证器里**用真实 payload 模拟 axios 的读取方式**（改 `readyState` → 触发 `readystatechange` → 读 `responseText`）；③**故意不给任何 DOM 数据**，只留 XHR 钩子一条路。结果 3/3 通过，视频拿到干净直链。

顺带发现并修掉一个真缺陷：详情接口的宽高在 `it.video.width/height` 上，原来只从 `it.width` 取，会让结果页显示 `0P`。

### 收尾第三批：仓库整理到「克隆即可构建」（同日完成，用户选定方向 A）

用户问「下一步要干嘛」，我先把仓库克隆到临时目录实测了一遍，结果暴露出**比清单上写的严重得多的问题**：

- **两个 README 都是服务器版文档**（仓库根与 `版本开发\纯本地APK版\` 一字不差），全仓库**没有一句话讲怎么构建 APK**。新人克隆下来完全不知道该干什么。
- 照文档根本构建不出 APK。逐层挖出**四个真缺陷**：
  1. **`cap copy` 不生成 `android\capacitor-cordova-android-plugins\`** —— 该目录被 gitignore 排除、却又是 `app\build.gradle` 的依赖。全新克隆必报 `Could not read script 'cordova.variables.gradle' as it does not exist`。正确命令是 **`cap sync`**（`android:sync` 脚本原本写的是 `copy`）。
  2. **CLI 7.x 把 Java 版本生成为 21，而本项目必须 JDK 17** —— `@capacitor/cli` 是 **7.4.3** 而 `@capacitor/android`/`core` 锁定 **6.2.1**，属**版本错配**。`cap sync` 会把 `app\capacitor.build.gradle` 和 cordova 插件工程的 `build.gradle` 都写死成 `VERSION_21` → `无效的源发行版：21`。这两个文件都无法入库（一个在 gitignore 目录内、另一个注释明说每次 update 重新生成），故新增 `android\fix-java-version.mjs` 挂进 `android:sync` 每次自动修正。
     > **这个坑最阴险的地方**：本机工作副本一直"能构建"，是因为那两个文件早被人手改成 17、且增量编译复用了旧产物；**只有全新克隆触发真正重编译才暴露**。这是"在我机器上是好的"的教科书案例。
  3. **`.gitattributes`（我自己上一批加的）把 `.cmd` 转成 LF** → cmd.exe 把行拆错，报 `'DK"' 不是内部命令` 这种莫名其妙的话。已加 `*.cmd text eol=crlf`。
  4. **`build-apk.cmd` 三处写死机器信息**：SDK 绝对路径、Gradle 缓存的 hash 目录名（`90cnw93cvbtalezasaz0blq0a` 在本机实际无效，正确的是 `78qddjpeqn5v6yec3xb8kv9ca` —— **hash 每台机器都不同**）、wrapper 指向本机无缓存的 8.14.3。已重写为自动探测（SDK：环境变量 → `local.properties` → 常见路径；Gradle：PATH → 用户级/项目级缓存 → wrapper 兜底），wrapper 也对齐到本机已有的 8.9。
- 另外修掉若干失真文档：`版本说明.md` 停在 v2.0 且仍宣称「抖音动态照片可解析」（已下线）；`.local-version` 状态是 `local-parser-pending`（早已完成）；`package.json` 版本号是 `1.0.0`、`android:apk` 脚本调 `gradlew.bat` 而不用我们自己的脚本。
- 还验证了**构建可复现**：本地重跑同一源码，APK 的 SHA256 完全不变；全新克隆产物与本地产物 **406 个打包条目大小全部一致**（SHA 差异来自 debug 签名时间戳，属正常）。
