# DECISIONS — 开发规范

## 2026-11-01 用户拍板(四问四答)

| 问题 | 用户选择 | 理由 |
| --- | --- | --- |
| 管哪些项目 | **所有有界面的项目**(APK/Web/小程序/桌面端) | 只卡 APK 会漏掉同类事故;纯脚本/后端自动走简化流程,不增加负担 |
| 卡点强度 | **全阶段硬门禁**(五个门都等用户点头) | 用户明确要"每关都停",宁可慢也不返工 |
| 设计稿形式 | **可点击 HTML 高保真原型 + 设计 token + 截图** | 静态风格图/文字方案看不出真实界面,是这次翻车的直接原因 |
| 落地方式 | **三处一起**(AGENTS.md 红线 + ui-first-dev 技能 + 项目文档模板) | 单靠文档不会被加载;单靠 AGENTS 几行没有模板支撑 |

## 设计上的关键取舍

1. **"选方向"而不是"给一套稿让人评价"** — 用户不是设计师,让他从 A/B/C 里选比让他判断"好不好看"容易决策,也避免做完才发现不对味。
2. **P1 出"每屏四态"** — 丑的常见来源不是配色,而是空数据/加载/报错用了原生默认样式。把四态划进 P1 而不是 P2,逼着在设计阶段就想清。
3. **Token 是唯一取色来源** — 没有 token,页面越多越乱;顺带让"禁止硬编码"可被 grep 检查。
4. **例外必须留痕** — 用户有权说"跳过",流程的义务是记进 `docs/DECISIONS.md`;否则规范会在第一次赶工时无声失效。
5. **规范正文单点权威** — README 只做索引,避免两份规则互相矛盾;变更记 WORKFLOW.md 末尾。

## 明确没做的

- 没有为"纯后端/脚本"设重流程(用户选项里已排除)。
- 没有引入 Jira/看板类外部工具:门禁靠对话完成,产物落项目 `docs/`。
- 没有强制老项目补历史文档:只要求新页面/改视觉走流程,新产物进 `docs/`。

## 2026-11-01 原型脚手架的范围取舍

- **决定**:四态演示只做在列表屏;深色模式不做;标签字号取 14(不写 12);危险操作统一走可复用 `data-confirm` 弹层组件。
- **理由**:模板要同时当"标准样例"和"可复制脚手架",体积与维护成本得压住;"正文最小 14px"优先于"角标做小更精致";二次确认是 `CHECKLIST-UI.md` D 组的硬要求,做成组件才能在真实项目里复用。
- **否决**:深色模式(超出模板必要范围,属真实项目的可选项,不做进模板)。

## 2026-11-01 仓库命名:中文项目名 → ASCII 仓库名

- **决定**:项目目录叫 `开发规范`,GitHub 仓库用 `dev-workflow`(私有)。
- **理由**:克隆地址/命令行更稳,避免 URL 编码问题;与既往仓库命名习惯一致(全 ASCII)。大脑仓库目录仍用中文名,两边不一致属已知,记在 NEXT「已知坑」。
- **否决**:仓库也用中文名(地址与终端处理麻烦,收益为零)。
