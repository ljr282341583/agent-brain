# DECISIONS — 开发规范

## 2026-11-01 用户拍板(四问四答)

| 问题 | 用户选择 | 理由 |
| --- | --- | --- |
| 管哪些项目 | **所有有界面的项目**(APK/Web/小程序/桌面端) | 只卡 APK 会漏掉同类事故;纯脚本/后端自动走简化流程,不增加负担 |
| 卡点强度 | **全阶段硬门禁**(五个门都等用户点头) | 用户明确要"每关都停",宁可慢也不返工 |
| 设计稿形式 | **可点击 HTML 高保真原型 + 设计 token + 截图** | 静态风格图/文字方案看不出真实界面,是这次翻车的直接原因 |
| 落地方式 | **三处一起**(AGENTS.md 红线 + ui-first-dev 技能 + 项目文档模板) | 单靠文档不会被加载;单靠 AGENTS 几行没有模板支撑 |

## 设计上的关键取舍

1. **"选方向"而不是"给一套稿让人评价"** — 用户不是设计师,让他从 A/B/C 里选比让他判断"好不好看"容易决策,也避免做完才发现不对味。
2. **P1 出"每屏四态"** — 丑的常见来源不是配色,而是空数据/加载/报错用了原生默认样式。把四态划进 P1 而不是 P2,逼着在设计阶段就想清。
3. **Token 是唯一取色来源** — 没有 token,页面越多越乱;顺带让"禁止硬编码"可被 grep 检查。
4. **例外必须留痕** — 用户有权说"跳过",流程的义务是记进 `docs/DECISIONS.md`;否则规范会在第一次赶工时无声失效。
5. **规范正文单点权威** — README 只做索引,避免两份规则互相矛盾;变更记 WORKFLOW.md 末尾。

## 明确没做的

- 没有为"纯后端/脚本"设重流程(用户选项里已排除)。
- 没有引入 Jira/看板类外部工具:门禁靠对话完成,产物落项目 `docs/`。
- 没有强制老项目补历史文档:只要求新页面/改视觉走流程,新产物进 `docs/`。

## 2026-11-01 原型脚手架的范围取舍

- **决定**:四态演示只做在列表屏;深色模式不做;标签字号取 14(不写 12);危险操作统一走可复用 `data-confirm` 弹层组件。
- **理由**:模板要同时当"标准样例"和"可复制脚手架",体积与维护成本得压住;"正文最小 14px"优先于"角标做小更精致";二次确认是 `CHECKLIST-UI.md` D 组的硬要求,做成组件才能在真实项目里复用。
- **否决**:深色模式(超出模板必要范围,属真实项目的可选项,不做进模板)。

## 2026-11-01 仓库命名:中文项目名 → ASCII 仓库名

- **决定**:项目目录叫 `开发规范`,GitHub 仓库用 `dev-workflow`(私有)。
- **理由**:克隆地址/命令行更稳,避免 URL 编码问题;与既往仓库命名习惯一致(全 ASCII)。大脑仓库目录仍用中文名,两边不一致属已知,记在 NEXT「已知坑」。
- **否决**:仓库也用中文名(地址与终端处理麻烦,收益为零)。

## 2026-11-01 全局化:三层落地 + 跨机安装包

- **决定**:规范做三层落地——① `~/.dsh/AGENTS.md` 全局红线(本机所有会话)、② `workspace/AGENTS.md` §2.6 工作区级(工作区自己的规则文件里也指向规范)、③ `install/install-machine.ps1` 跨机一键安装;并把 `ui-first-dev` 按工作区 Skills 管理规则登记进 `skills/registry.md`。
- **理由**:只做 ①,工作区规则文件里看不到这套流程,agent 读工作区规范时不会联想到;只做 ①②,换一台机器就失效。三层分别覆盖"本机任意会话 / 工作区内协作 / 新机器"。
- **否决**:
  - 把 `workspace` 根 `git init` 纳入版本管理——工作区含大量与本规范无关的资产,改动面过大、且不是用户诉求。
  - 让安装脚本同时改 `workspace/AGENTS.md`——该文件不属于本仓库,路径与内容因机器而异,改为提供现成片段(`install/workspace-agents-2.6.md`)手动贴,更可控。
    > ⚠️ 已被 2026-11-01「工作区根改为自动探测」取代:脚本现已能改 `workspace/AGENTS.md`,但先探测工作区根、探测不到就只提示,片段仍作为兜底保留。

## 2026-11-01 工作区根改为自动探测(不写死路径)

- **决定**:`-WorkspaceAgents` 默认值由"空"改为 `auto`;探测顺序 = 当前目录向上 → 本仓库根向上 → DSH 登记表 `%DSH_HOME%\storages\workspace.json` 里登记的路径;判据为"目录下有 `AGENTS.md` 且(`skills\registry.md` 存在 或 `AGENTS.md` 含'工作区通用协作规范')";探测不到只打印提示并跳过,支持 `-WorkspaceAgents <目录|文件|none>` 覆盖。
- **理由**:用户质疑原示例里写死的 `G:\ai\deepseek harness output\workspace\AGENTS.md` 在另一台电脑未必成立——这个路径只是 A机 当前工作区根,不是常量。写死会在 B机 上静默改错地方或报错。
- **否决**:在文档里保留"把本机路径改成你的路径"的手工步骤——路径因机器而异,让人手填就是把易错点交给用户。

## 2026-11-01 跨工具适配:DSH + Codex + Claude Code

- **决定**:规范正文保持**工具无关**(纯 md/html);把"机制层"按工具各铺一份——DSH(`.agents\skills` + `.dsh\AGENTS.md` + 工作区 §2.6)、Codex(`.codex\skills` + `.codex\AGENTS.md`)、Claude Code(`.claude\skills` + `.claude\CLAUDE.md`);安装脚本加 `-Target dsh|codex|claude|all`(默认 all,未安装的工具自动跳过),本机三套已铺好。
- **理由**:内容层本来就能被任何 agent 读,卡住的只是"谁会自动加载它"。用户实际装了 Codex(`~\.codex\AGENTS.md` 已有自定义规则)、Claude(`~\.claude` 已有 skills 目录),且既有习惯就是"AGENTS.md 为主指引、CLAUDE.md 作指针"(见 ds-harness-desktop),按同一模式适配成本最低、心智一致。
- **否决**:为每个工具重写一份不同措辞的规则——三份内容一旦漂移就会互相矛盾,统一用 `redline-template.md` + `workspace-agents-2.6.md` 两个来源生成。
- **备注**:本机 `claude` 命令不在 PATH(未装 CLI 或未加路径),`~\.claude\CLAUDE.md` 已按约定铺好;真正用 Claude Code 时它默认读该文件。Cursor 等读项目根 `AGENTS.md` 的工具,靠规范仓库的说明即可,暂不单独适配。
