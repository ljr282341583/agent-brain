# CONTEXT — 开发规范(UI 优先 + 全阶段门禁)

> 新会话 / 另一台机器开工前必读。规范正文权威版本在项目目录里,本笔记只记思路与理由。

## 项目是什么

一场"流程事故"的产物:用户让 agent 开发 APK,agent 跳过 UI 设计直接写代码,成品界面丑。用户要求把整个工作空间的开发流程规范化。

本项目不做业务功能,产出是**一份可被 agent 自动执行的规范** + 配套模板,以及**三处落地机制**(缺一处就落不了地):

| 落地点 | 路径 | 作用 |
| --- | --- | --- |
| 主规范 | `G:\ai\deepseek harness output\workspace\projects\开发规范\` | 正文、清单、模板、可点击原型脚手架(人读 + agent 复制) |
| 技能 | `C:\Users\Administrator\.agents\skills\ui-first-dev\SKILL.md` | 触发即加载,带每阶段动作与门禁话术 |
| 全局红线 | `C:\Users\Administrator\.dsh\AGENTS.md`「开发流程红线」 | 每次会话自动注入,强制加载技能、禁止跳过设计 |

## 流程骨架(2026-11-01 定版 v1.0)

P0 需求卡 → **门禁①** → P1 UI 设计(2–3 套风格方向二选一 → 全屏可点击高保真原型 + design-tokens + 每屏截图)→ **门禁②(最硬)** → P2 前端实现(mock,1:1 还原)→ **门禁③** → P3 接口契约 + 后端 → **门禁④** → P4 联调验收(真机/三宽截图)→ **门禁⑤** → P5 交付与收尾。

- 门禁统一用「门禁汇报卡」:产物 / 结论 / 差异遗留 / 下一阶段 / 请用户确认。
- 四道保险专治"快但丑":设计先行、token 统一、每屏四态、截图走查。
- 例外四通道:A 修 bug、B 单屏小迭代、C 紧急上线(P1 记技术债)、D 用户要求跳过(说清后果 + 写 DECISIONS 留痕)。

## 关键文件

- `WORKFLOW.md` — 唯一权威正文(阶段/门禁/反丑 10 条/例外/目录标准/复盘/变更记录)
- `CHECKLIST-UI.md` — 交付前自检 A–G 七组 + 30 秒判丑
- `README.md` — 入口索引(用户视角的"怎么说、看什么"),不重复规则
- `templates/` — PRD / UI-DESIGN / API-CONTRACT / ACCEPTANCE / design-tokens.json / prototype/index.html(5 屏原型脚手架 + shots 截图)

## 与既有体系的关系

- 与大脑仓库「跨机接力约定」互补,不冲突:门禁决策落项目 `docs/DECISIONS.md`,收尾仍走 `session-handoff` 写大脑仓库。
- `教程1-日常开发流程.md` 讲的是 git/大脑仓库的接力,不讲 UI 流程;本项目补的是"开发怎么做"这一段。
